📝 Adding your interview experience#

This is the highest-value contribution. Open an issue using the "Interview Experience" template, or submit a PR adding to the relevant company section.

Include:

  • Company, role, year, and whether it was on-campus or off-campus
  • Your background at the time — year, CGPA, DSA count, projects. (This is what makes it useful — it tells readers what level actually clears the bar.)
  • Every round, in order, with the actual questions asked
  • What you got wrong and what you'd prepare differently
  • Outcome (selected/rejected) — rejections are just as valuable as selections

Anonymise freely. You don't have to use your name. You can say "a tier-3 college in UP" rather than naming it. Never include anyone else's personal details.

✅ Contribution guidelines#

Do:

  • Keep the tone honest and specific. This repo's value is that it doesn't sugarcoat
  • Use simple English — many readers are more comfortable in another first language
  • Verify before adding. Check that links work and salary data is current
  • Match the existing formatting — headers, tables, callouts, emoji use
  • Keep contributions focused. One topic per PR

Don't:

  • Add paid courses, referral links, or affiliate links of any kind
  • Promote your own YouTube channel, community, or bootcamp
  • Add motivational filler without concrete information
  • Add unverified salary figures or hiring claims
  • Copy content from other repos or blogs without attribution
  • Add resources behind a signup wall or paywall

Important

This repo is free forever and stays free. Any PR adding a paid course, an affiliate link, or a "DM me for guidance" promotion will be closed without discussion.

🔧 How to contribute#

Small fix (typo, broken link)#

Use GitHub's web editor — click the ✏️ pencil icon on any file, make the change, and open a pull request. Takes 2 minutes, no local setup.

Larger contribution#

# 1. Fork the repo on GitHub, then:
git clone https://github.com/sumitsingh4411/Placement-Preparation-Roadmap.git
cd Placement-Preparation-Roadmap

# 2. Create a branch
git switch -c add-zoho-interview-experience

# 3. Make your changes, then:
git add .
git commit -m "add Zoho SDE interview experience (2026, tier-3, off-campus)"
git push -u origin add-zoho-interview-experience

# 4. Open a Pull Request on GitHub

Not sure if your idea fits?#

Open an issue first. Describe what you want to add and we'll discuss it before you spend time writing.

📐 Style guide#

  • Headings: sentence case, with a leading emoji for top-level sections
  • Tables: wrap in <div align="center"> for consistency with the rest of the repo
  • Callouts: use GitHub alerts — > [!NOTE], > [!TIP], > [!IMPORTANT], > [!WARNING]
  • Links: relative paths for internal files ([DSA](core/dsa.md)), full URLs for external
  • Checkboxes: - [ ] for anything the reader should do
  • Currency: write Indian salaries as ₹12 LPA, not 12 lakhs per annum or $15k
  • Long lists: wrap in <details><summary> so files stay scannable
  • Voice: direct and second person. "You need 300 problems", not "students should aim for 300 problems"

🐛 Reporting problems#

Open an issue for:

  • Broken or dead links
  • Outdated information (a company changed its hiring process, salary bands shifted)
  • Something factually wrong
  • Something confusing or hard to follow
  • A missing topic you think should be covered

Please include: the file, the specific line or section, and what's wrong.

🌍 Translations#

Translations are very welcome — a lot of students would use this more comfortably in their own language.

How: create README.hi.md, roadmap/year-1.hi.md etc., preserving the structure and all links. Add a language switcher line at the top. Open an issue first so two people don't translate the same file.

💬 Code of conduct#

Be decent. Specifically:

  • No gatekeeping. "You should have started in 1st year" helps nobody in their 4th year
  • No college shaming, in either direction
  • No salary flexing. Share numbers as useful data, not as status
  • No discouragement. "Tier-3 se kuch nahi hota" is both wrong and unwelcome here
  • Assume good faith. People asking basic questions are just earlier in the journey than you

Behaviour that's demeaning, harassing, or discriminatory gets contributions closed and access removed.

🙏 Recognition#

All contributors are credited. If you add an interview experience or a substantial section, you'll be listed in the contributors section of the README.

The best thing you can add is what you wish you'd known two years ago.#
